## 0. 이 문서 사용법

- Claude Code는 세션을 시작할 때마다 이 파일(`docs/plan.md`)과 `docs/progress.md`를 먼저 읽는다.
- **지금 진행할 단계: I2 (설치·속도 실측).** I1(문헌·검증 자료)은 Claude Science가 병행하며, 결과 파일은 사용자가 `docs/`에 넣는다.
- I2를 시작할 때 이 파일 §2의 규칙을 그대로 저장소 루트 `CLAUDE.md`로 복사한다.
- 단계 시작 프롬프트(사용자가 매번 붙여 넣음):

```text
docs/plan.md와 docs/progress.md를 읽고 I□ 단계를 진행해.
먼저 계획(바꿀 파일, 실행할 명령, 예상 시간·비용)을 보여주고 내 승인을 받아.
같은 원인으로 3번 실패하면 멈추고 '오류 보고' 양식과 승급안을 제시해.
끝나면 성공 기준 통과 여부를 근거와 함께 보고하고 progress.md를 갱신해.
```

물리식을 다루는 단계(§4에서 UT O)는 프롬프트 끝에 `ultrathink`를 붙인다.

## 1. 목적과 연구 질문

2D/3D 램·스크램제트 흡입구 하나를 마하 0.6~7로 올리고 내리면서, 시동·불시동이 어떤 경로로 바뀌고 벽면 열유속이 어디서 얼마나 치솟는지 OpenFOAM으로 추적한다.

| 번호 | 질문 | 단계 |
|---|---|---|
| Q1 | 마하 구간별 흡입구 유동 구조와 성능(전압 회복 η, 포획 유량비 MFR) | I7 |
| Q2 | 시동 경계 vs Kantrowitz·등엔트로피 한계, 마하 상승/하강 히스테리시스 | I8, I9 |
| Q3 | 하류 스로틀링 시 의사충격파열 → 버즈 → 불시동 순서 | I10 |
| Q4 | Edney IV, SBLI, 경계층 천이가 열유속 정점을 키우는 정도 | I11, I12, I15 |
| Q5 (확장) | 가열 소스항 열 질식으로 램→스크램 이중 모드 전이와 불시동 연결 | I16 |

결론은 "이 형상·이 모델 계급에서의 상대적 경향"으로만 주장한다. M > 7, 실기체 효과, 실제 연소는 범위 밖이다.

## 2. 절대 규칙 (→ `CLAUDE.md`로 복사)

```markdown
# CLAUDE.md — 흡입구 실험 (Inlet Mach sweep)

## 환경
- WSL2 Ubuntu. 소스·빌드·케이스·출력은 반드시 ~/ 아래. /mnt/c 에서 빌드·쓰기 금지.
- OpenFOAM ESI v2512 + HiSA. 다른 판본으로 바꾸려면 사용자 승인.
- 노트북: i5-1340P 12코어/16스레드, RAM 16 GB(WSL 10 GB), NVIDIA GPU 없음.
  로컬 실행은 MPI 최대 8 프로세스(기본 4 — I2 실측에서 np 4 이상은 빨라지지 않음, D-009), 메모리 10 GB 이내.
- sudo가 필요한 명령은 직접 실행하지 말고 명령을 보여준 뒤 사용자가 실행하게 한다.

## 절대 규칙
1. 물리·수치 계수(난류 모델 상수, 리미터, 인공 점성, Sutherland 계수, 벽 조건,
   경계조건 종류)는 사용자 승인 없이 바꾸지 않는다. '안정화'를 이유로 바꾸는 것도 금지.
   바꿀 때는 제안 → 승인 → 케이스 설정과 커밋 메시지에 기록.
2. 벽 함수 사용 금지. y+ 기준:
   - 정상 계산·열유속을 보는 케이스: 벽 첫 셀 y+ < 1
   - 충격파 거동만 보는 비정상 케이스(I9, I10): y+ ≤ 5 허용
   scripts/yplus_check.py 로 자동 검사, 위반 시 실패 처리.
3. 열유속은 scripts/heatflux.py 하나로만 계산한다(벽으로 들어가는 방향이 양수).
4. 기체 상수·γ·Sutherland 계수는 src/constants.py 하나에서만 가져온다.
5. 정상 판정: 질량 유량 불균형 0.5% 미만 + 감시 지표(η, 최대 열유속)가
   마지막 2,000 스텝 동안 0.2% 이내. 이 기준 없이 '수렴'이라고 보고하지 않는다.
6. 초음속 출구에 압력을 지정하지 않는다. 배압은 하류 저항 영역(fvOptions)이나
   스로틀 형상으로만 만든다.
7. 클라우드 리소스 생성·삭제·결제 전에는 예상 비용을 보여주고 사용자 확인을 받는다.
   작업이 끝나면 인스턴스를 즉시 삭제한다.
8. 클라우드 실행은 1시간 간격 체크포인트, 자동 재시작, 결과 즉시 동기화.
9. 모든 실행 결과에 케이스 설정 전체와 git 커밋 해시를 남긴다.
10. 새 검증·분석 코드는 해석해 테스트(pytest)를 먼저 통과시킨 뒤 쓴다.
11. 논문의 식을 구현할 때는 주석에 출처(저자, 연도, 식 번호)를 단다.
12. 확실하지 않으면 추측하지 말고 질문한다. '그럴듯한 그림'을 성공으로 보고하지 않는다.
13. 단계가 끝날 때마다 docs/progress.md 에 한 일, 결과, 남은 문제, 소요 비용, /usage 를 적는다.

## 오류 3회 정지 규칙
- 같은 원인의 실패(명령·컴파일·실행 실패, 발산·NaN·음수 온도/압력, 성공 기준 미달)가
  3번 나면 즉시 멈춘다. 원인이 바뀌면 새로 센다.
- 다음 '사전 승인 수치 조정'은 실패로 세지 않고 먼저 써 본다(순서대로, 각 1회):
  (a) CFL을 낮게 시작해 점진 증가  (b) 1차 정확도로 시작 후 2차로 전환
  (c) 이전 마하수 해 또는 균일 자유류로 초기화  (d) 국소 시간 간격 켜기(정상 계산만)
  이 목록을 다 써도 실패하면 그때부터 1회로 센다.
- 멈추면 docs/progress.md 에 '오류 보고' 양식으로 적고 승급안을 제안한 뒤 승인을 기다린다.
- 계수를 키워 발산을 숨기는 것은 시도로 치지 않으며 금지한다.
- 클라우드 비용이 단계 예상치의 150%를 넘으면 1회만에 즉시 정지한다.
```

## 5. 기술 설정

| 항목 | 값 | 비고 |
|---|---|---|
| OpenFOAM | ESI v2512 | HiSA 공식 지원 범위(ESI v2006~v2512)의 최신판 |
| 정상 솔버 | HiSA (내재적 밀도 기반, 국소 시간 간격) | I7, I8, I9, I11a |
| 비정상 솔버 | rhoCentralFoam, 또는 HiSA가 비정상을 지원하면 HiSA | I2에서 결정 |
| 기체 | 완전기체 공기, Sutherland 점성, JANAF 비열 | |
| 난류 | k-ω SST(압축성 보정) | I15에서 SA와 비교 |
| 벽 | 기본 등온 300 K, y+ 규칙은 §2 | |
| 형상 | 2D 혼합압축(외부 램프 2단, 카울, 일정 단면 아이솔레이터), 설계 마하 약 5 | 설계 마하 아래 불시동은 결함이 아니라 결과로 다룸 |
| 마하 점 | 0.6, 0.8, 0.95, 1.1, 1.5, 2, 2.5, 3, 4, 5, 6, 7 | 비행 동압 일정 궤적 |
| 후처리 | Python(numpy, scipy, matplotlib, pyvista, fluidfoam), ParaView는 Windows 쪽 | |

### 격자 수렴(I6) 판정
- 전압 회복 η의 GCI ≤ 3%
- 적분 열부하와 열유속 정점 **위치**의 GCI ≤ 5%
- 열유속 정점 **값**은 관문으로 쓰지 않고, GCI를 오차 막대로 보고한다.

### 알려진 위험 메모
- Edney IV는 본질적으로 비정상이라 정상 계산이 수렴하지 않을 수 있다. I11a에서 2회 미수렴이면 비정상 계산으로 전환을 제안한다.
- M ≥ 6에서 충격층 정적 온도가 2,000 K를 넘으면 결과에 '완전기체 가정 한계' 경고를 붙인다.
